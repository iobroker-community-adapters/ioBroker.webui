# Repository instructions

## Project memory

- Read `memory/README.md` and the relevant files under `memory/` before making project changes.
- Treat `memory/` as this repository's durable project knowledge base and keep it under version control.
- After a material change, record durable decisions, non-obvious constraints, known quirks, and verified commands in the relevant memory file.
- Update or replace stale entries instead of appending contradictory notes. Date status-dependent facts and distinguish verified facts from hypotheses.
- Keep memory concise and point to source files where practical. Do not store secrets, credentials, personal data, hidden reasoning, raw logs, or short-lived debugging details.
