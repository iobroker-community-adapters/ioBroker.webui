# AI assistant

Implemented 2026-11-10. Sources inspected: ioBroker.vis-2 `src/lib/ai.ts`, `src/main.ts`, and `src-vis/src/AiChat/*`; ioBroker/ai-core 0.0.6; ioBroker/ai-gui 0.0.5; ioBroker.ai-server main.

- vis-2 uses `@iobroker/ai-core` and its React `ai-gui` frontend, rather than directly depending on ai-server. webui uses the same AiBackend, system.ai settings and push-answer protocol, with a native webcomponent UI to avoid introducing React/MUI into the designer.
- ai-core 0.0.6 requires a manager credential for model listing even on keyless custom endpoints. The backend normalizes a system custom provider without a credential ID to manual/no-key mode, retaining its saved endpoint. This matches the core chat path and is covered by the local-provider integration test.
- `src/backend/main.ts` wires messagebox, AI lifecycle and UI subscription callbacks. System credentials/endpoints stay server-side. No adapter-specific credential fields are added. Node minimum is 22.19.0.
- Client IDs use getRandomValues when randomUUID is unavailable: plain HTTP LAN origins are common in ioBroker and do not expose randomUUID.
- `src/frontend/ai/AiClient.ts` registers pending requests before sending (answers can beat acknowledgement), correlates concurrent turns, and rejects pending requests on disconnect. Instance-message subscriptions are required; older controller/web versions show an update message.
- ai-core ships CommonJS. `scripts/ai-shared-entry.mjs` explicitly re-exports `runToolLoop`; `npm run bundleAi` creates a browser ESM bundle. Copy only that shared bundle into www and map its exact import in importmap-config. Bundling the CommonJS index directly exposes only a default export and breaks browser startup.
- The AI panel needs an explicit side-effect registration import in the shell. A class import used only as a generic type is erased by TypeScript.
- Tools inspect saved/open documents, global config, palette definitions and generated script/property schemas; ioBroker object search returns selected common metadata only, excluding native/custom/ACL data. State reads use the logged-in socket; no write-state or script-execution tool is exposed.
- Turns stage proposals. Apply compares the current complete snapshot with the read snapshot and opens/updates an editor; Save remains explicit. A later turn reading a changed document discards its stale pending proposal and rebases on current source. Each applied AI proposal is one document undo transaction, restoring HTML, separate CSS/JavaScript models, settings and typed properties together; earlier manual history is preserved. New/unopened documents are opened with their original (or empty unsaved) baseline before applying.
- IndexedDB stores chats (including attachments/source context) per origin, adapter instance and ioBroker user. Storage errors leave chats usable in memory. Reload marks running turns stopped. Stop aborts the local wait immediately and prevents further tools; it cannot cancel an already-running provider request in ai-core 0.0.6.
- Text/source and PNG/JPEG/WebP/GIF attachments: eight files, 10 MB per message. OpenAI-compatible multimodal messages are forwarded unchanged. ai-core 0.0.6's Anthropic translator handles text only: the panel explicitly rejects screenshot chats for that provider.
- Live paid-provider behavior was not exercised. Browser fixtures and a passing local HTTP provider integration test cover the UI/protocol without contacting user services.

## Composer and docking — 2026-11-10 follow-up

- Chats are materialized on first Send. The starting view lists chats above a fresh-draft composer; clicking a row opens the conversation, and Back returns to the list without stopping other runs. A separate draft is stored under the same scoped IndexedDB key with `:draft`. Running rows show animated rings; background replies/completions set a persisted unread dot, cleared when the chat is viewed. Chat rename/delete actions use a keyboard-accessible context menu (right-click or Shift+F10), with no chat-management toolbar.
- Conversation bubbles place user messages on the left and AI replies on the right, with distinct themed surfaces. Consecutive tool outputs are collapsed into “AI work” between messages; proposal review cards and Apply/Discard actions appear immediately below the next AI answer after staging, outside the collapsed work group. Source JSON stays behind its own disclosure. Pending proposals without an answer (Stop/error), and legacy proposals without entry links, remain visible at the end of the conversation. Apply still requires explicit review/action.
- Compact provider/model controls and attach/microphone/send/stop actions live below the text field, following VS Code's chat-input placement. Enter sends, Shift+Enter inserts a newline. The field stays editable while running.
- `AiTurnController.ts` injects steering only at model-request boundaries. Tool calls from an in-flight answer are skipped when guidance is waiting, and their matching tool results are retained so the transcript remains valid. Stale answer text is kept out of the visible chat while steering waits. Guidance arriving with a final answer triggers a new request. Queued messages run only after the current turn completes. Stop/error/reload cancels unsent pending work. Pending attachment edits preserve image/source payloads.
- `AiClient.ask` supports AbortSignal to end local waits and ignore late pushed answers. Shared subscriptions remain usable by other chats. This does not cancel remote generation in ai-core 0.0.6.
- `AiSpeechInput.ts` wraps SpeechRecognition/webkitSpeechRecognition. Interim/final text fills a draft, never auto-sends; manual edits, switching chats, closing the dock or disposal cancel dictation and ignore late events. Unsupported/denied speech is explained in the panel.
- AI starts auto-hidden on the right rail. Closing parks the same connected dock element in the shell's light DOM, preserving live sessions and their client. `showAiAssistant()` reattaches and opens it through the dock observer; do not recreate the chat or call dispose on Close. Its close control is keyboard-accessible.
- Test fixture controls are explicitly labelled “Test fixture · Mock backend” and are absent from production HTML. The fixture shell uses `temporary-ai-sessions`: chats stay in memory and never restore or save IndexedDB history. Old mock history is ignored; real user scopes are untouched. Optional fixture URL parameters `aiDelay` and `speechFixture=1` enable pending-message/dictation checks without a real provider or microphone.

## npm tools and activation — 2026-11-10

- `list_packages` returns capability matches plus installed widget dependencies; `describe_package` returns repository-backed package metadata/tag lists, with optional tag-specific manifest API identifiers. Descriptions are dated snapshots, not guarantees about an older installed version. `add_package` accepts only exact suggested names and does not save or reload screens. Luma remains eligible once published; registry/installation errors are surfaced.
- `AiPackageService.ts` handles atomic `ai:addPackage` messagebox calls: validate server-side, serialize against AI/manual npm work, skip reinstall when already present, rebuild/upload widget files, and report completion/version or error. Existing packages are republished to recover previously failed loader generation. npm runs with `--ignore-scripts`; nonzero exits/spawn failures are distinguished from successful installation. Stop cannot roll back a backend npm operation already started.
- Policy lives in `src/shared/NpmPackagePolicy.ts`. `.npmignore` excludes root `/dist/frontend`: backend must read the allowlist from packaged `www/dist/frontend/npm/usable-packages.json`, never import root frontend JS. Integration startup caught this packaging constraint. Shared compiled files are included in both server and browser output.
- `LoadInstalledPackages.ts` refreshes the import map, registers new manifests, imports widgets, and registers addons without page navigation. Generated manifest/addon registration accepts the previously registered package names to avoid duplicate services. Legacy module observation is retained across refreshes. Addon config reads are awaited before publishing generated glue.
- Tool results distinguish npm success from browser readiness (`editorReady`, registered tags, activation error text). An npm install can succeed while an import fails; the AI must report that distinction. Existing editor contents remain untouched.

## Authored editor context — 2026-11-10

- `get_editor_context`, `list_windows`, and `read_window` expose the last non-AI focused panel, current document, selected authored elements, and chunked unsaved code-editor text. Style/JavaScript dock wrappers are resolved to their Monaco child; their model identifies the owning screen. AI focus does not replace the last content panel.
- Selection paths count only authored element children, not text/comments or designer overlays. `stage_element_attributes` patches the read snapshot via the existing HTML parser and stages a normal proposal; full snapshot conflict checking on Apply remains intact. Supports paths and unique simple #id/.class/tag selectors. The parser fork advertises querySelector APIs in types but does not implement them; do not call them.
- `read_document_field` provides bounded source chunks while establishing the proposal's read base. Documentation explicitly prefers the separate style/script fields and JSON simple scripts, and documents converter condition order/defaults. Focused edits support @event attribute names and HTML-encoded JSON without executing scripts.
- Screen property initialization accepts defined falsy defaults (0, false, empty string), matching their typed document representation.

## Lazy component and asset discovery — 2026-11-10

- `list_elements` now searches/paginates palette definitions and saved reusable controls; `describe_element` exposes control properties/settings, webui-owned APIs, or installed custom-elements manifest facts before falling back to the dated package catalog. Saved control definitions take precedence over duplicate palette entries. Component/object metadata snapshots expire after 10 seconds; package activation invalidates the component cache.
- `AiAssetCatalog.ts` enumerates one directory level at a time: this instance's image library, discovered installed icon adapters, and flot/echarts chart presets. Paths/namespaces are constrained. Metadata reads avoid image bytes; chart configuration is chunked and selected fields exclude credential keys. Chart presets expose saved configuration/embed URLs, not rendered chart screenshots.
- `view_asset` rasterizes requested image/icon assets to PNG with a 1024px maximum dimension (10 MB read/40 MP limits), at most four per turn. The panel appends a multimodal user message at the next model-request boundary, after all tool results; binary data never appears in tool-result strings. Vision needs an appropriate model; the current Anthropic bridge remains text-only.
- Node tool tests import root `dist/frontend/ai/AiTools.js`: packaged www dependencies omit package.json and rely on browser import maps, so Node bare-module resolution there fails once tools import the HTML parser. Browser fixtures verify actual import-map resolution.


## AI proposal undo — 2026-11-10

- `applyAiSnapshot` parses replacement DesignItems before mutation and rechecks the full current snapshot after the asynchronous parse. `AiSnapshotTransaction` then synchronously swaps prepared DesignItems and restores all document metadata/models through the existing undo service. Undo/Redo retain DesignItem identity needed by earlier manual undo entries. Save remains explicit.
- CSS replay uses `updateCompleteStylesheetWithoutUndo` before synchronizing the model/container. Setting additionalStylesheets directly emits an asynchronous extern stylesheet event and creates a second undo entry; do not use that alone for replay. Monaco model edits here belong to the document transaction rather than separate Monaco entries.
- Opt-in browser regression: `/test/browser/designer-smoke.html?contextReview=1`, expand the explicitly labelled fixture controls and click “Verify AI context and undo”. Uses actual designer/Monaco/undo/binding/image-preview APIs with a fake socket, never a user controller/provider. Verifies all five fields, prior manual history, Redo, delayed CSS synchronization, authored selection paths, focused bindings, SVG preview, numeric converter behavior, parser failure atomicity and a new screen's empty undo baseline.

## Message timing and conditional costs — 2026-11-10

- New user/assistant entries persist optional numeric timestamps; the UI displays local date/time with ISO `<time datetime>`. Older entries have no invented timestamps. `AiTurnController` supplies answer time and elapsed milliseconds covering provider/tool rounds; queued requests start timing when delivered, steering continues the active request. Timing metadata stays outside model messages.
- `AiChatMetadata.ts` accumulates explicit reported monetary metadata only: `estimatedCost` or `cost` as `{amount,currency}`, or a numeric amount with explicit top-level `currency`. Currency must be a three-letter code and amount finite/nonnegative; zero is valid. Totals keep currencies separate, include tool-call replies and replies suppressed by steering, and say “partial” when some replies lack reports. No token-price inference or currency defaults.
- Installed ai-core 0.0.6 and upstream main `src/shared/types.ts` / `src/shared/response.ts` currently expose token counts, not monetary costs (verified 2026-11-10). The conditional UI is ready for explicit cost metadata if forwarded; any future upstream monetary schema must match/be normalized before use. Cost-free responses produce no price/placeholder in the list/footer.
- Browser fixture `?costFixture=1` explicitly injects monetary metadata for UI verification only; it does not call a paid provider. Verified timestamp/elapsed display, list/footer totals, and hidden cost fields in the default no-cost fixture. Node tests cover missing/invalid money, multi-currency/zero/partial totals, saved legacy history and full-loop/queued timing.

## Detached AI dock — 2026-11-10

- AI window moves retain the same panel/client/session store and any active turn. Popup close returns the live dock to the main rail; detachment must not run shell disposal or park the AI in the main light DOM. `adoptedCallback` moves visibility listeners to the new document and cancels speech/menu UI; chat context menus use the owner document's events and viewport. DOM creation uses ownerDocument. Workspace window/screen discovery includes live detached panels.
